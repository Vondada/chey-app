# GPU Browser and persistent rendering

CHE reuses the retained `creation-gpu` WebView and existing Connect GPU flow. Back/Forward navigate page history; Back at the first page does not exit. Close returns to CHE, without clearing cookies or revoking Google grants. The status panel can still hide/expand by voice.

Connect CHE Office opens Google's account chooser in the system browser using the existing PKCE OAuth callback. Only `openid email` is requested; Google userinfo must return a verified email and subject. Access and refresh tokens use CHE's existing encrypted server storage. Switching replaces only the Office grant. Normal access refresh does not open consent. Google can still require reauthentication. The verified email updates the existing Colab account preference and notebook `authuser` hint. This grant does not authenticate the Colab WebView or prove a GPU connection; Google controls those sessions separately.

Render in Live 3D Studio uses the existing project/version queue. The same version reuses queued, running or completed work, including jobs created before this update. An edited/new version gets its own request key. IDs, progress, errors, checkpoints and output receipts remain on the backend. A Durable Object alarm retries capacity/recovery every minute while unpaused jobs remain, preserving earlier alarms from other rooms. The existing provider authorization and zero-spend gates still apply. GPU-required jobs wait if no authorized GPU is available; compatible jobs can use the existing free public-repository CPU worker. No iPhone browser is required for that server worker.

GPU labels require fresh non-CPU heartbeats; Rendering additionally requires a matching running job. Reconnecting compute means a backend cloud dispatch is recorded, and explicitly says the GPU is disconnected. Setup Required and failed status checks never claim a connection. Colab cannot be remotely started by CHE or guaranteed an unlimited T4 lifetime; Reconnect opens one notebook action for the owner.

The existing deploy workflow also accepts `[creation-check]` on a main push. Its real Blender check leaves all phone/browser clients absent for a minute, waits for completion, downloads the actual GLB, checks its SHA-256 against the receipt and loads it in CHE's viewport. Automated Google responses and widget tests are not evidence of a real Google login or iPhone closure test. Image/video creation retains its existing pipelines; this change does not implement new video synthesis.
