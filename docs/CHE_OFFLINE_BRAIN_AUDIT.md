# CHE Offline Brain: audit (owner, 2026-10-28)

Scope of this audit: what is in the repository now, what runs on an iPhone, and what is missing. Every claim has a file or
command as evidence. Nothing here is a device test: no iPhone was available to this session.

## 1. Native iPhone code: the gap that matters most

- `ios/` is gitignored (`.gitignore` line 12). The iPhone project is generated by `tool/bootstrap.sh` (2033 lines).
- The Dart side calls two method channels that the generator **does not implement**:
  - `che/local_ai` (`lib/che_native_voice.dart`, `CheLocalAI.respond` and `available`)
  - `che/local_brain` (`lib/che_local_brain.dart`, the on-device model: `generate`, `load`, `verify`)
  - `grep -c "local_ai" tool/bootstrap.sh` → 0; `grep -c "local_brain" tool/bootstrap.sh` → 0.
- Consequence (from the code, not yet measured on a device): a call to either channel raises `MissingPluginException`,
  which `CheLocalAI.respond` turns into `null`. **On-device language-model inference does not run on the iPhone today.**

## 2. What does exist

| Area | Where | What it does | Offline? |
|---|---|---|---|
| Speech (on device) | `tool/bootstrap.sh` (SFSpeechRecognizer, AVSpeechSynthesizer) | Speech recognition and an iOS voice | Yes, when the iOS speech model is installed; not measured here |
| Bluetooth audio | `tool/bootstrap.sh` lines ~801–970 | `allowBluetooth`, `allowBluetoothA2DP`, route-change and interruption handlers | Yes (device); car behaviour not tested |
| Local storage (server) | `server/cloudflare/library.js` (SQLite, FTS) | Saved documents and search | Server only, not on the phone |
| Capability registry | `server/cloudflare/capability_registry.js` | Promotion checks (functional, security, resource, license, output, regression, rollback); VERIFIED/AVAILABLE gate | Server only |
| Deterministic math | `server/cloudflare/arithmetic.js`, `numeric_truth.js` | Exact arithmetic; equation checks in replies | Pure code: no network needed |
| Scene document | `server/cloudflare/scene_document.js` | Validated 3D scene model with undo/redo | Pure code |
| Offline reply path | `lib/home_state/streaming.dart` `_tryLocalOfflineResponse` | Falls back to cached or on-device answers | Only as far as the on-device model works (see §1) |
| Connectivity recovery | `lib/home_state/streaming.dart` | Retries the Worker; falls back on 5xx/timeout | Partly |

## 3. What is missing

1. A native implementation of `che/local_brain` and `che/local_ai` in the generator. Options (not chosen yet):
   - **Apple Foundation Models** (`SystemLanguageModel`, `LanguageModelSession`): on-device, no per-token cost, but it
     needs a supported iPhone and iOS version with Apple Intelligence enabled. Availability must be checked on the owner's
     phone. This session cannot verify it.
   - **llama.cpp with the pinned GGUF** (`CheLocalBrainModel` in `lib/che_local_brain.dart`): runs on any supported device,
     needs a native build and a model download (size and licence to be checked by the owner before any download).
2. Persistent encrypted local memory on the phone: none exists; memory lives on the Worker.
3. Offline sync and conflict handling: none exists.
4. An Offline Brain screen: none exists.
5. Device benchmarks (latency, battery, storage, speech, memory retrieval) and Airplane Mode tests: none exist, and they need
   the owner's iPhone and car.

## 4. Evidence that this session could produce now

- `server/cloudflare/offline_capabilities.test.mjs`: runs the pure scene model (`scene_document.js`, on `main`) with network
  access blocked and checks that a saved scene is built, edited and read back. It also checks that the block is real.
- Exact arithmetic (`arithmetic.js`) runs with no network too, and its offline proof is part of PR #737. That code is not on
  `main` yet, so it is not claimed in this PR.

## 5. Not claimed

- No on-device model answers offline today.
- No Apple Foundation Models or llama.cpp integration exists or has been tested.
- No battery, latency, storage or Bluetooth measurement has been made.
- The car's Bluetooth connection has not been tested.
